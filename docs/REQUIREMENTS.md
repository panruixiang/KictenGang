# KitchenGang（厨房帮）· 决策汇总

> 这是做需求划分的**唯一入口**。术语定义见 [CONTEXT.md](../CONTEXT.md)，单个决策的完整来龙去脉见 [docs/adr/](./adr/)。
> 状态：**需求澄清已完成**（29 条决策）。

## 一句话定位

给一个家庭内部使用的做菜工具：家人共享同一个私密菜谱库，对外不可见。微信小程序方向。

## MVP 范围（已确认）

| 能力 | 决策 |
| --- | --- |
| A · 照着菜谱做 | 搜索 / 收藏 → 打开步骤引导（计时器、步骤勾选） |
| A+ · 份量换算 | 做菜时可选"几个人吃"，按份量比例**当场换算每条配料用量** |
| B · 按食材反查 | 从食材字典勾选"我有什么" → 找出能做的菜；默认勾上"我家常备食材"；**调味料不参与匹配**（视为默认有） |
| 录入方式 | 纯手动录入（唯一方式） |
| 种子内容 | 内置 5-10 道"几大菜系常见菜"，**只读**；想改就复制一份成自家菜谱，并记住来源。反向：维护者可把自家菜谱**提升为内置**（种子维护手段，非公开发布） |
| 菜谱字段 | 名称、封面图、配料、步骤 + **份量 / 耗时 / 难度 / 菜系分类标签**（后四项均为选填；**份量录入时预填 2 人份**） |
| 配料与用量 | 配料 = 食材 + 用量；食材取自**规范词表**，用量是**"数字 + 单位"**（单位取自小表）或特殊值"适量"（不参与换算） |
| 图片 | **仅菜谱一张封面图**；做菜记录不配图 |
| 收藏 | **每个成员各自收藏**；家庭共享收藏后置 |
| 记录模型 | 菜谱 + 做菜记录 两个实体；做菜记录可把改动另存为菜谱的一个版本 |
| 做菜记录的关联 | 菜谱**可选**（可随手记一笔，日后补成菜谱）；版本**可选**（可标"这次用的是少辣版"） |
| 做菜记录的字段 | 菜谱（可选）+ 版本（可选）+ **备注**（自由文本）+ **本次配方**（可就地改的配方副本） |
| 食材模型 | 规范食材词表（薄版本：覆盖内置菜 + 常见家常食材，几百条量级）；**每条带分类**（主料 / 辅料 / 调味料） |
| 空间归属 | 一个成员**可属于多个厨房空间**；同一时间只有一个"当前空间" |
| 加入空间 | 通过**微信分享的小程序卡片**加入（带参卡片 → 云函数校验 → 写成员表）；其它方式后置 |
| 权限 | 空间内完全平权：任何成员都能改、能删任何自家菜谱与版本 |
| 变更记录 | 每次保存菜谱 / 版本都写一条（谁、何时、改了什么）；查看界面后置 |
| 端形态 | 微信小程序为主，架构上保留 Web 端；**Web 界面不进 MVP**，等小程序稳定后再评估 |
| 服务端 | 微信云开发（数据库 / 云函数 / 云存储 / 登录态），不自建后端 |
| 客户端技术栈 | uni-app（Vue 语法，一套代码可出小程序 + H5） |

## 明确不做（同样重要）

- 公开社区 / 对外分享；**公共社区板块与用户投稿**
- 库存管理与扣减（**"常备食材"不是库存**，它不记数量）
- 粘贴文本自动切分、AI 生成菜谱草稿
- 不可变的历史版本快照；修改历史的**查看界面**（变更记录本身要写，见 ADR-0001 修订）
- AI 对话、周计划 / 采购清单
- 做菜记录配图
- 家庭共享的收藏（个人收藏是 MVP）
- 邀请码 / 手动添加等其它入伙方式
- MVP 内的 Web 界面
- 自建后端与第三方 BaaS（MVP 阶段，见 ADR-0002）
- 内置菜谱的任何编辑 / 删除
- 成员之间的差异化权限
- 用量的自由文本写法（如"一小把""两勺半"）——见 ADR-0004

## 暂按默认处理（未正式讨论，做需求划分时请留意）

1. **搜索维度**：按菜名 + 菜系标签 + 食材搜索。（未讨论）
2. **步骤计时器**：每个步骤可挂一个可选的时长，做菜时倒计时。（未讨论）
3. **步骤引导的形态**：逐步勾选 / 翻页 / 常亮屏等细节。（未讨论）
4. **做菜记录的日期**：默认自动填当天，可改。（未讨论）
5. **"我家常备"的维护入口**：默认放在食材或设置页。（未讨论）
6. **新空间是否预置一批常备食材**：未讨论。
7. **食材字典的冷启动数据**：几百条，覆盖内置菜 + 常见家常食材，录入时可"新建食材"。
8. **单位表的初始清单**：g / ml / 个 / 勺 / 碗 之外还要哪些，未讨论。
