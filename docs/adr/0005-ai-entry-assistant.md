# 录入菜谱时提供"咨询型"AI 助手，但 AI 不碰表单数据

- 状态：Accepted（**实现后置**：微信云开发阶段落地，静态原型阶段不做）
- 日期：2026-10-14
- 关联：细化 Q2（AI 对话后置）的边界；修订"明确不做"清单中 AI 相关条目的表述

## 背景

ADR-0004 选择了食材与用量的**完全结构化**，代价是录入摩擦：配料要拆成"食材 + 数字 + 单位"逐行填、步骤要逐条组织语言、空表单有启动压力，长辈的打字意愿尤其低。2026-10-14 重新讨论"新建菜谱是否接入 AI"时，确认这些摩擦真实存在，但想要的形态**不是**"AI 一键生成菜谱"，而是：

> 自己填；不知道怎么填的时候，有个入口问一句 AI，拿到参考后仍由自己描述、自己填写。

Q2 原本将"AI 对话"整体后置，"明确不做"清单也列了"粘贴文本自动切分、AI 生成菜谱草稿"。本决策不推翻它们，而是在中间划出一条更窄的能力。

## 决策

在新建 / 编辑菜谱表单内提供**唯一的 AI 入口**——"录入助手"：

- **形态**：表单顶部一个入口，点开为底部半屏问答弹层（标题"录入助手 · 仅供参考"+ 消息流 + 输入框），空态给 3~4 个快捷问题示例。编辑已有菜谱时自动带上当前菜名作为上下文；除此之外不读取表单其他内容。
- **输出只供参考**：文字回答，步骤 / 用量用短列表组织，支持长按复制。**v1 不提供"一键填入"**，关闭弹层后表单内容保持不变。
- **能力范围（v1）**：用量与份量换算、步骤先后与火候时间、食材搭配与替代、烹饪名词解释。
- **范围外**：疾病 / 治疗性营养、婴幼儿孕妇等特殊人群膳食，礼貌拒答；"没熟能不能吃"类食品安全问题必须给明确风险提示，不含糊作答；与做当前菜无关的闲聊不响应。
- **数据归属**：AI 回答不自动成为菜谱数据。保存下来的菜谱，其每个字段都必须来自用户手动操作。
- **对话不落库**：v1 关闭弹层即清空，不存历史。

## Considered Options

- **字段级助手（配料区"帮我拆一句话"、步骤区"帮我理成几条"，AI 出草稿、人逐条确认采纳）**：最贴"配料拆行最重"的痛点，但它与已否决的"粘贴文本自动切分、AI 生成草稿"只隔一层窗户纸，多入口也显著放大成本与审核面。**列为二期观察项**：等单一助手上线后，若配料拆行仍是主要卡点再评估，且必须坚持"逐条人工确认才入库"。
- **非 AI 减负组合（语音转文字、步骤模板、常用配料快选、Q15 的随手记日后补全）**：零模型成本、零内容审核风险，对"不想打字"最有效，但解决不了"我根本不知道放多少、怎么做"的**知识性问题**。作为普通录入优化另行排期，不替代本决策；其中 Q15 已在 MVP 内。
- **AI 一键生成整份草稿 / 粘贴自动切分**：维持不做。菜谱是家庭长期复用的私人数据，步骤或用量错误会直接导致做菜翻车；自动成稿也架空了 ADR-0001"版本是用户自己的配方副本"的语义。

## Consequences

- 实现期（云开发阶段）必须同时满足：模型调用经**云函数代理**、密钥不下发到小程序端；用户提问与 AI 回答**双侧过微信内容安全检测**；首次使用告知"AI 内容可能有误，仅供参考"并在隐私协议中补充数据用途；按用户**限频**；超时 / 断网 / 内容被拦截时降级为"助手暂时不可用，先按你的经验填"，**手动录入主流程不受任何影响**。
- 验收口径：从表单任意位置 ≤ 2 次点击可发起提问；AI 内容不出现在任何表单字段中；固定问题集人工评估，常见四类问题绝大多数返回可操作建议。
- 需求侧：Q2 中"AI 对话后置"特指**独立的通用对话 / 计划型能力**（周计划、采购清单等），仍后置；本决策是绑定录入场景的受限问答，二者边界以本文件为准。
