# 食材与用量都结构化，不做自由文本

为了让两条核心能力成立——"按现有食材反查能做什么"（B）与"按人数换算用量"（A+）——食材和用量都必须**可计算**：

- **食材**取自一张规范词表，同实物的不同叫法（土豆 / 马铃薯 / 洋芋）归并为同一条；每条带分类（主料 / 辅料 / 调味料），其中**调味料不参与匹配**。
- **用量**拆成"数字 + 单位"，单位取自一张小表（g / ml / 个 / 勺 / 碗…），另有特殊值"适量"。

两者都**拒绝自由文本输入**。

## Considered Options

- **自由文本 + 模糊匹配 / 尽力解析**：录入最省事，但同义词永远对不上（"土豆" ≠ "马铃薯"）；用量也只有部分行能被解析——同一道菜里有的行缩放、有的没变。**均已否决**：在做饭这个场景里，"有时灵有时不灵"比"根本不做"更摧毁信任。

## Consequences

- 录入摩擦上升：录一道菜必须从词表里选食材、选单位。缓解手段：词表支持"新建食材"，单位用常见值预选。
- 换来一组以后能长期复用的地基：食材反查、份量换算，以及将来的采购清单与 AI 对话，全都建立在同一套结构化数据上。
- **食材词表与单位表的冷启动内容是实际工作量**（当前按"几百条食材"估），且必须覆盖内置的 5-10 道种子菜。
