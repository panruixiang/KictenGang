# 客户端用 uni-app，不用微信原生

客户端采用 **uni-app**。选它而不是微信小程序原生，是因为 Q4 已明确要为 Web 端保留位置：uni-app 能用同一套代码产出小程序与 H5，让 Web 端那天的前端成本从"重写"降到"适配"。团队背景是 Vue/TypeScript，uni-app 的学习成本接近零。

## Considered Options

- **微信小程序原生**：与已选定的微信云开发（ADR-0002）配合最顺——`wx.cloud` 直接调用、官方文档与示例几乎全是原生写法、调试链路最短。未选的原因：它与"为 Web 端留位置"这个已定目标自相矛盾，用原生等于没留。
- **Taro**：跨端能力同样扎实，但以 React 语法为主（Vue3 支持是次要路径），对 Vue/TS 背景的团队不算优势，中文生态与示例也少于 uni-app。

## Consequences

- **已接受的代价**：在 uni-app 里使用微信云开发需要多包一层，遇到问题时可直接搜索到的资料显著少于原生方案。这是为 Web 端的未来可能性付的现价。
- 若日后 Web 端被正式取消，这条决策应当被重新评估——原生的开发体验更好。
